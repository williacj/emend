How you'll work

Brainstorm. Revise. Review. Without leaving your files.

Three ways of working, one document at the center of gravity — everything deep-links into the text, and back.

1

Brainstorm → revise

Chat with an agent grounded in your repo — its skills, references, and past writing. Turn the conversation, or a pasted draft, into an AI-attributed set of tracked changes you review line by line.

2

Comment → addressed

Drop comments in the margin and let the AI address them. The fix arrives as tracked changes plus an explanation; accepting the change resolves the comment, rejecting it reopens. The agent can push back without editing.

3

Skill-based & human review

Run staged, gated review workflows built from your own repo skills — or invite people. Findings and reviewer suggestions land as severity-tagged, attributed comments you address personally or delegate.

What's inside

A real editor, with an agent wired in — not a chat box bolted on.

An agent that proposes

Claude Code and GitHub Copilot as peer providers, grounded in your repo. Any protected document only ever receives changes as tracked changes — never a surprise edit.

CLAUDE CODE + COPILOT

Word-style tracked changes

Redline with attribution, four display modes, per-change accept/reject and batch triage. Substitutions, insertions, deletions — all first-class, all reversible.

CRITICMARKUP, IN THE FILE

Lossless markdown

GFM plus YAML frontmatter round-trip with structural fidelity — the editor is the source, with no serializer between what you see and what's on disk.

SOURCE-AS-MODEL

One unified timeline

Your comments, AI review findings, reviewer suggestions, and tracked changes are one chronological stream with filters — not four competing panels. Provenance is always visible.

CHAT · COMMENTS · CHANGES

Review without git

Invite a reviewer — even a non-technical one. They sign in and redline; branches, worktrees, and pushes stay completely hidden. Git surfaces only as “start review,” “accept review,” “history.”

GITHUB BACKBONE

Portable & yours

Skills and workflows are repo-owned Claude Code files — fully usable from the plain CLI without Emend. Comments and changes live in documented sidecar formats. No proprietary store, no lock-in.

NO LOCK-IN
The loop

From a blank page to a reviewed draft.

A project is any folder — git isn't required. Local features work anywhere; sharing lights up when you connect a repo.

Brainstorm into being

Chat is repo-level, so a document is born into the conversation. When an idea is ready, the agent creates the draft and the editor opens it — the thread stays attached.

Revise as tracked changes

Ask for a revision and it lands as an attributed change-set. Keep writing while the agent works — it's visible and never blocking, and it asks for shell permission inline, never with a modal.

Review & ship

Run a gated skill review or invite people. Decide every change, resolve what you can, and accept the review — Emend squashes it home and cleans up the branch behind the scenes.

“Nothing changes a protected document without an accept. The UI never applies, auto-scrolls, or steals focus on the agent's behalf.”
— Emend design principle #2: Propose, don't surprise
Non-negotiables

Built so your words never depend on us.

These aren't features to toggle — they're invariants the app is designed around.

The file is the truth

The markdown on disk is the single source of truth. Round-trip fidelity is structural — Emend is a cockpit over your files, not a database that owns them.

Runs on your machine

A true macOS and Windows desktop app — it keeps working offline and your words stay on your device. All agent and network activity originates locally, under your control.

Secrets stay put

Credentials live in the OS keychain only. Nothing sensitive is written to your repo, and secrets are never logged.

Git is invisible

No branch names, commit buttons, or push prompts. Publishing is always a deliberate human act — the agent never pushes on its own.
