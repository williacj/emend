**Rulings:** CJ, 2026-09-30 and 2026-10-01. The existing `4a` (Windows) and `4b` (macOS) mocks show a collapsed Timeline with comments. Draw their missing states without hand-editing `docs/design/` in this repository. `docs/design/specs/state.md` still lists no-comments as undrawn and Q13.1 as open; the next generated refresh should close that stale gap. ## Frames to add

1. **File-backed document, confirmed no comments:** the comments column remains in the right rail at its existing **400px** width. After that document's comments load succeeds with no threads, keep its ordinary column chrome and place the quiet message `No comments in this document` in its empty body. Pending or failed load cannot claim zero; this brief does not prescribe a loading or error treatment. The editor does not widen. No zero-count badge should suggest an action or unresolved work.
2. **Switch tabs while collapsed:** show a commented file-backed tab, then an uncommented one, then back, with `timelineCollapsed` unchanged in that window. The column content follows the active document, including its empty message. Include the **untitled** destination: the same 400px column instead reads `Comments are available after Save As`, because comments cannot attach to that pane yet (J12, UXR-Q14.3). Workshop mode, with no open document, has no right rail.
3. **Address with AI from a collapsed comment card:** keep the comments column visible and place a link to the new run on that comment card. Draw the case where the submitted run carried the active document's unsaved text, with `Unsaved text sent with this run` beside the link. Draw a clean or D31-over-bound comparison with the same run link and **no** sent-text claim. Activating the link uses the existing `Timeline ››` rail transition to reveal and focus that run, then its J13 card line supplies the full record. The link must remain distinct from the comment anchor/gutter deep link.
4. **Return to the composer:** show the collapsed `Timeline ››` chip and expanded Timeline. The message input, provider switcher, mic, and J13 standing disclosure all live in expanded Timeline. They do not occupy a second row in the comments column. The existing timeline rail is **372px** wide; switching occupants may change the rail from 400px to 372px, as `docs/design/specs/authoring-shell.md` already specifies.
5. **Run started outside a persistent comment card while collapsed:** show the author pressing `Address all…` from the comments column and, separately, file-backed selection `Ask agent` from the editor. Submission expands Timeline to reveal the new run and the **applicable J13 outbound disclosure on the submitted-turn card that owns it**: a user chat card where the route creates one, otherwise the run card (J13 Phase B). Include a within-bound dirty document, a D31-over-bound comparison, and a clean-document comparison with **no outbound line**: the over-bound card says `carried <name> by name only — over Cowrite's size limit` on that owning card, never `Unsaved text sent with this run`. For a route with no user chat card, show the queued or running run state and the successful run card's default collapsed state, whose outbound line remains visible and directionally distinct from inbound `files read`. Show the current facet already containing the run, then a facet that excludes it: only the latter switches to `All` so the run and applicable disclosure are in view. Do not attach a second cue to the `Address all…` source or the selection popover. The comment-card exception in frame 3 stays collapsed.

## Appearance and interaction details to resolve in the generated design

- Carry Windows `4a` and macOS `4b` backgrounds, card treatment, title/chip treatment, and focus ring conventions through each frame (`specs/comments.md`, `specs/authoring-shell.md`, `specs/platform-variants.md`, `specs/tokens.md`). The two platform variants need the same words and behavior. Do not infer a new dark mode or sub-1400px responsive rule from these frames.
- Show the empty messages as low-emphasis text in the column body, legible at 400px and distinguishable by wording alone. Neither message is a button; `Save As` in the untitled message names the route, but this ruling does not turn the sentence into a new control.
- Give the in-card run link a clear name and keyboard focus state. Its activation expands Timeline, reveals the corresponding run, and moves focus to the **run card container**, with a visible focus indication; never to `[Stop]`. Tab switching leaves focus in its ordinary context and does not focus an empty message. The `Timeline ››` chip remains keyboard reachable in all collapsed states.
- Keep the brief sent-text disclosure readable beside the link without letting a narrow card clip or hide the fact. It is plain explanatory text, not a second link or a copied payload. Show enough card states to make clear that it is conditional on text **actually sent**. J13's over-bound `by name only` detail remains on the linked run card.
- Draw the transition from the 400px comments column to the 372px Timeline, the new run's visible landing position, and keyboard focus after each run-start action. The source action may disappear with the collapsed column or selection popover; focus must not land on `[Stop]` or a permission decision. Preserve the editor caret, document scroll, review position, and active document. Show a visible keyboard focus target for both the comments-column and selection-popover starts. The exact focus target after submission is an interaction detail for the generated design to propose; it must keep the new run and applicable J13 disclosure reachable without a second hidden navigation step.
- Keep J7 permission attention separate: a permission request arriving later does **not** itself expand Timeline, change the facet, or move focus. The existing Pause badge and author-activated navigation remain its route. Likewise, switching tabs alone preserves the window's collapsed preference; the automatic expansion above is caused by the author's run-start action.
