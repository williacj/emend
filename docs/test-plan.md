## 1. Strategy: test where the risk lives

The architecture was chosen to make the worst bugs *impossible* (fidelity by construction) or *pure* (textops). The plan exploits that:

| Layer | What lives there | Risk profile | Technique |
|---|---|---|---|
| `textops/` (pure Rust) | anchors, TD-6 transforms, CriticMarkup, event folds, diff→edits, re-anchor | **Highest consequence, fully deterministic** | Property-based testing (proptest), corpus tests |
| Rust services | sync engine, sidecar stores, session manager, MCP server, checkpointer | Stateful, I/O-heavy | Integration tests vs **local bare repos** + **fake agent CLI**; no network |
| Frontend | editor decorations, timeline, stores | Visual/state | Vitest component tests; decoration snapshot tests |
| End-to-end | J1–J8 as executable acceptance scripts | Integration seams | Playwright against the production frontend joined to the real backend (D23 hook, see below); fake agent by default |
| Live-provider smoke | real Claude Code / Copilot sessions | Non-deterministic, costs money | Thin scripted scenarios; cadence → Q1 |

**The fake agent** is the plan's keystone: a scripted stand-in CLI that speaks the same stream-JSON events and calls the same MCP tools as the real thing, driven by per-test scripts ("read 2 files, request permission, deliver this change set, die mid-run"). It makes every agent journey — including interruption, permission, partial delivery, protection violation — **deterministic and CI-runnable**.

**What "the real app" means in the e2e row (CJ-ratified 2026-08-06, spike #1137 §§7, 9 — wording only).** The suite drives the **unmodified production frontend** served by Vite in Chromium, joined to the **real Rust backend** through `crates/test-driver`'s loopback HTTP surface over the same command functions the Tauri IPC layer calls (`playwright.config.mjs`, tech-design §3.7). Production modules, production stores, real backend commands, real files on disk — only the *transport* between them differs, which is what §7b permits and bounds. It is **not** `tauri-driver` against a packaged native webview: `tauri-driver` supports Linux (WebKitWebDriver) and Windows (WebView2) only, and macOS WKWebView has no WebDriver/CDP story — the constraint resolved 2026-07-15 (journal, P2a-2/#142) and re-checked unchanged 2026-08-04 (#1137 §7). **The constraint is not reopened here**; only §1's earlier "Playwright/WebDriver against the real app" wording, which described a rig that cannot exist on the primary dev platform and so kept inviting "drive the real app" to be re-litigated. Two seams stay uncovered by construction — the Tauri `invoke`/`listen` bridge and the native file/folder dialogs — and are accounted for in §7b's exemption list rather than left silent.

**Contract parity (keeps the fake honest):** the provider contract is machine-readable — JSON Schemas for the stream-JSON event grammar and MCP payloads live beside `docs/formats/`. (a) Fake-agent output is schema-validated in every e2e run; (b) live smoke **records real-CLI transcripts** and validates them against the same schemas — the version-drift canary is "recorded real session still parses under the schema the fake is built from"; (c) transcripts recorded during SPIKE-1 become replayable adapter-test fixtures. **Required misbehavior repertoire** (scripted, not incidental): raw file-write to a protected doc *with* correlated stream events (exercises attribution precedence), malformed/oversized/interleaved output, never-terminating stream (watchdog), stale-revision tool calls, mid-delivery death.

## 2. Property-based invariants (textops)

The load-bearing guarantees, expressed as properties over generated inputs (random GFM docs, random edit sequences, random markup):

- **P1 No drift under operations:** arbitrary sequences of *view operations* (display-mode toggles, source-view flips, frontmatter fold/unfold, cursor reveal-at-markup) leave the document string byte-identical; save∘load ≡ identity (incl. BOM/final-newline/encoding via atomic save) is the cheap base case. The threat isn't a serializer (none exists) — it's a projection that mutates instead of projects.
- **P2 Anchor tracking:** for any doc, any anchor, any edit sequence: anchor follows exact-mapping when untouched; snapshot+context re-anchor lands on equal text when it exists; else orphan — **never a wrong silent position, never a dropped comment** (D17).
- **P3 Coordinate transforms (TD-6):** clean/displayed are pure functions of raw; the *position mapping* raw↔clean round-trips exactly for positions outside markup regions, with a defined, tested policy for positions inside them (raw→clean is lossy — this mapping, not a bijection, is what anchors depend on).
- **P4a Independent-change convergence:** for *non-overlapping, non-group-linked* changes over *structure-stable documents*: accept-all ≡ clean text; reject-all ≡ original; any decision subset in any order converges. Generators treat nested/adjacent/whitespace-only markup as first-class, plus the old-app regression corpus (cursor-restore, whitespace-leak). *Domain note (CJ-ratified 2026-07-15, #75/#183):* convergence assumes no decision changes the block structure that classifies other markers — a resolution that reveals marker-shaped literal text or leaves line-start indentation (the indented-code exclusion) can reclassify a later marker on re-parse, and stepwise apply then legitimately diverges from batch apply; generators enforce structure-stability (delimiter-free content charset, letter-leading document start), and the divergence outside the domain is pinned as documented behavior (`resolving_a_change_may_reveal_marker_shaped_literal_text`, `resolving_a_change_may_reindent_a_later_marker_into_code`).
- **P4b Group semantics:** deciding any member of a group (substitution pair, linked set) decides the group atomically, all-or-none — in interactive triage *and* within TD-7 partial apply (one context-stale edit stales its whole group).
- **P5 Event-log folds under causality:** generators produce **cross-author causal chains** (create→reply→resolve→reopen→re-anchor split across author files) folded under adversarial interleavings; dangling references (child before parent) have deterministic defined semantics (buffer-until-parent); timestamp ties/clock-skew handled; **incremental-sync invariant:** fold(prefix) then remaining ≡ fold(all); unknown event types skipped, not fatal.
- **P6 Delivery rebasing (TD-7):** for any concurrent user-edit sequence: applied ∪ rejected partitions the proposal; applied = exactly the context-matching edits (groups all-or-none per P4b); application atomic — no observable intermediate state.

Corpus source (TP-Q3): **open-source fixture corpus** — public-domain long-form prose from Project Gutenberg incl. actual public-domain sermons (Spurgeon/Wesley/Edwards — structurally matches the target workload), CommonMark+GFM spec example docs (systematic feature coverage), permissively-licensed technical docs (tables/code/frontmatter variety); fixture manifest records source + license (public domain/CC0 preferred, CC-BY ok, no NC/SA). Edit histories synthesized against these docs from SPIKE-4's real-session edit patterns (patterns travel; prose doesn't). Real `biblical_writing` zero-drift check remains a local-only release-gate step on CJ's machine.

## 3. Integration tests (Rust, no network)

- **Sync engine (TD-3/§3.2b):** author + reviewer workers against *local bare repos* as remotes — push races (bounded retry), union-merge of same-author JSONL on two branches, worktree lifecycle (create/mirror/complete/cancel/crash-repair), offline queue persistence across process restart, D18 completion (squash, pull-into-dirty-main, sidecar survival), TD-8 checkpointer (debounce, no-op on non-git).
- **MCP contract (TD-1):** every tool — happy path, stale revision (TD-7 partial-stale response), protection violations (D21 matrix: open tab / review set / operation target / unprotected), auth (wrong bearer token rejected), malformed payloads.
- **Session manager (TD-5):** queue order (FR-AGENT-7), stop = process-group kill with clean state, watchdog, crash mid-run → FR-AGENT-6 invariant checked on the doc, resume, provider-switch transcript seeding.
- **Stores:** sidecar schema round-trip vs published JSON Schemas (`docs/formats/` — the contract *is* a fixture), D22 importer (old `.comments/`/`.track-changes/` → events, idempotent), docs.json rename/adopt flows, per-project lock.
- **Project files (TD-18; `NI-project-files-refresh-visibility`, `NI-project-files-native-rename`, `NI-project-files-recreate-confinement`):** pure snapshot/reconcile fixtures cover visibility, unreadable/root-failure retention, coalescing, event-during-refresh, optional/duplicate platform identities, directory descendants, and case-only spelling changes. Real platform-gated integration tests exercise notify's shipped macOS `RenameMode::Any` and Windows tracker-less `From`/`To` shapes plus the native identity adapters, including spaces, Unicode, and near-260-character Windows paths. An injected `SidecarStore::rename_all` `@anchor:test-plan-sidecar-store-rename-all` fail-then-retry proves a retained candidate can still carry live state/history. Recreate tests prove macOS/unsupported adapters return `ConfinementUnavailable` before any content read or filesystem write; Windows holds root, ancestor, parent, and temp handles without `FILE_SHARE_DELETE`, rejects reparse traversal, prevents a barriered ancestor relocation for the whole transaction, and fails capability acquisition before content/temp/target I/O when pre-existing `DELETE` access conflicts. Existing no-overwrite and two-writer races remain: `EEXIST` returns status without reading the target, and exactly one writer returns `Created`.
- **GitHub API layer:** octocrab behind a trait; recorded-response tests for PR create/comment-import (idempotent by comment ID)/merge/close; rate-limit backoff honored.
- **Checkpointer × concurrent-git-actor matrix (TD-8):** checkpoint vs user's own git state (merge/rebase in progress, detached HEAD, staged-but-uncommitted index — never eats/entangles the user's staging), vs review-sync mirror commit, vs D18 completion pull, vs TD-7 write-hold; checkpoint commits never trigger the app's own FR-ED-7 banner; commit scope = docs + `.cowrite/` only.
- **Security (FR-X-2, TD §3.5):** path confinement per tool/IPC parameter (`..`, symlinks, null bytes, absolute-outside, Windows case-insensitivity + near-260 paths); MCP loopback-only bind; token leakage sweep (exercise auth flows, then scan structured logs for token material — automated); **attribution precedence both directions** — positively-attributed agent write → convert; unattributable write (git checkout, external editor) → FR-ED-7 banner, *never* convert on a guess.
- **Migration (D22) with counted pass criteria:** old threads/replies/resolutions/changes in = events out, per file; every anchor resolves to equal text or is a *counted* orphan (quote preserved; orphan list manually verified once); re-run byte-idempotent; upgrade atomic with defined old-file disposition. Ugly cases: truncated/corrupt old JSON, mixed old+new sidecars, line/col anchors from CRLF-era files (the off-by-one nest).
- **Voice positive path (FR-ED-5):** WAV fixtures → pinned model (cached CI artifact; openly-licensed, ~57MB) → expected transcript (tolerance-based); capture layer behind a trait (mockable devices); download manager (interrupted/corrupt → recovery); ghost text **never** enters undo history, finalized text does; identical state machine across all three surfaces.
- **Named-invariant sweep (seeded into `docs/test-matrix.md` before build step 2):** undo policy (deliveries `addToHistory:false`; accept/reject single undoable entries with sidecar versioned alongside; undo-accept-inside-group; user-edit-inside-pending-change) · spellcheck suppression in markup/frontmatter ranges · keymap module per-platform + J1 triage keys in e2e · settings persistence **+ settings schema versioning/migration** · J7 notification defaults at dispatch level · timeline collapse/facet-jump *correctness* (not just perf) · FR-SKILL-1/5 discovery as plain integration tests (frontmatter parse, ignore dirs, config override) · accessibility: severity color+letter rule and one **keyboard-only** J1 triage e2e.

## 6. Performance budgets (numbers set by SPIKE-3; tracked benchmarks, not PR gates)

Wall-clock assertions on shared CI runners are institutionalized flakiness — so budgets run as **benchmarks on a dedicated/consistent runner** with relative regression thresholds; only gross regressions (>2× baseline) hard-fail. Targets:

- Open + render 1MB doc with 500 markup regions: < target ms, no frame > 100ms (FR-X-4).
- Keystroke latency under full decorations: p95 < 16ms.
- Delivery apply (200-edit change set) write-hold: < 250ms (TD-7's "sub-second").
- Timeline with 5k cards: scroll jank-free (virtualization test).
- Fold of 10k-event comment log: < 50ms.

## 7b. Substitution discipline — what a test may stand in for (CJ-ratified 2026-08-06, spike #1137)

"No mocking in e2e" is binding (CLAUDE.md, Standards above) but was not checkable. Spike #1137 traced the #1118/#1120/#1121 blind spot to substitution discipline rather than tooling — the timeline card factory behind #1120 had five test callers and **no production caller**, and every test still passed — and found no stated test by which a reviewer could have caught that. This section is that test.

> **A test may substitute the TRANSPORT that carries a call. It may never substitute a PARTICIPANT that makes or handles one.**

**Operational check — name the producer and the consumer of the substituted value.** Both ends production code, only the wire or the cadence between them changed ⇒ transport. The test script standing at either end ⇒ a mock, whatever it is called.

(The injectable-clock seams that comments throughout `src/` and `e2e/` already cite as "test-plan §7" are *stated* in §4's determinism discipline and *judged* here — which is why this rule lands at §7, where the codebase has long looked for it.)

| Substitution | Producer | Consumer | Verdict |
|---|---|---|---|
| `callBackend` `@anchor:test-plan-call-backend`'s HTTP fallback to `crates/test-driver` | real backend command fn | real frontend module | **Legitimate** — only the wire changed |
| A `/run_state` poll standing in for the `agent://activity` push | real `RunQueue` `@anchor:test-plan-run-queue` | production `foldRunStatus` `@anchor:test-plan-fold-run-status` | **Legitimate** — only the cadence changed |
| The driver's cursor-backed `/events` long poll standing in for Tauri event push | real backend observer / explicit OS-menu stand-in | production shared event pump and mounted handler | **Legitimate** — only the wire changed; the test never calls an app handler |
| `openProject` `@anchor:test-plan-open-project` / `openProjectFolder` `@anchor:test-plan-open-project-folder` | the test script | production `App.openProjectRoot` `@anchor:test-plan-open-project-root` | **Legitimate, narrowly** — stands in for the native OS folder dialog, which is outside the app |
| `setAutosaveIntervalMs` `@anchor:test-plan-set-autosave-interval-ms` / `setExternalChangePollMs` `@anchor:test-plan-set-external-change-poll-ms` / `setCommentNowMs` `@anchor:test-plan-set-comment-now-ms` | the test script | production clock reader | **Legitimate** — §4's injectable clock; it substitutes *time*, not a participant |

`/run_state`'s polling cadence is not allowed to erase lifecycle events. Its `finished` field is an
ordered, cumulative terminal ledger for the current open-project lifetime: every terminal is
inserted once by stable run id, replayed on every poll, and deduplicated client-side by the stable
id plus its full status fingerprint. A newly mounted subscriber therefore receives terminals that
raced its mount; a successful project replacement/close clears the ledger under the queue's idle
lock so history never crosses project lifetimes. A same-root open that reaches the under-lock
concurrency recheck is `AlreadyOpen`, not a replacement, and preserves that same project's history.
Retention is deliberately complete within that
lifetime—one frozen status, including its activity lines, per submitted run—because no durable
per-subscriber acknowledgement cursor exists; a numeric cap would turn a slow/remounted subscriber
back into the same silent-gap defect. Terminal cards themselves remain D15-persisted as before.

The D23 `/events` stream uses one monotonically increasing server cursor plus a project epoch/floor.
Entries are append-only for the current open-project lifetime and replay independently without a
destructive drain; a same-root open retains them, while only a successful replacement/close clears
and advances the epoch. The browser persists the shared epoch/cursor across reload and multiplexes
all five event names through one in-flight long poll, so remounting does not replay already-consumed
facts and one channel cannot drain another's notice. A driver restart is detected by epoch even when
the stored cursor is ahead. Server waits end on event, epoch change, or a one-second cap; at most
eight `/events` workers exist, each response socket has a one-second write deadline so a
non-reading client cannot retain its permit, and ordinary driver commands remain on their serial
authority lane. Frontend dispatch isolates every subscriber; the shared cursor advances and
persists only after every event in that batch had a chance to reach all current handlers.

**Corollary A — every test-only hook names, in one line at its definition, the out-of-process actor it stands in for:** an OS dialog, a provider CLI, the wall clock, the user's hands. A hook that stands in for *the app's own code* is a mock. The `openProject` pair, native-dialog results, and clock seams pass. **Every former `notify*` hook is now retired:** #1826 replaced agent-activity injection with `/run_state`; #1827 replaces delivery and document-birth injection with the driver's backend-produced event log. Tests never call those production handlers directly.

**Corollary B — a bare `if (!isTauri()) return <empty>` in a production module is a silent coverage hole:** it makes the production path unreachable under the acceptance suite while every test still passes. Each such branch is either **routed through `callBackend`** or **carries an entry in the exemption list below with its reason**; `backend.ts`'s own `isTauri()` switch `@anchor:test-plan-is-tauri-switch` is excluded, since it *is* the transport. Adding a branch without doing one or the other is a review finding, and a PR that adds or removes one updates this list in the same change.

**Exemption list** — re-counted against `src/` on 2026-09-03: **5 branches across 3 modules**. (#1513 first routed project-files refresh; #1395 routes settings/transcript request-response; #1826 routes activity; #1827 moves project files plus delivery, birth, Open, and Save As onto one shared event pump. A routed branch carries no bare `if (!isTauri())` no-op of its own left to list.)

The settings request/response pair now also carries #1395's caller-discrimination proof (#1832): a user changes a non-default autosave interval through the production Settings surface, reloads and reopens the project and Settings, and sees that persisted value through a fresh production read. The acceptance case calls no settings driver helper or test-only settings hook; D23 substitutes only `callBackend`'s transport to the real driver-backed settings store, and removing either `SettingsDialog` `@anchor:test-plan-settings-dialog` production caller makes the post-reload value assertion fail.

The run request/response pair carries the matching #1825 caller-discrimination proof. In an assembled non-Tauri `TimelinePanel`, two user submissions travel through the production composer and `agentActivity.startRun` `@anchor:timeline-start-run`; the queued acknowledgement exposes the production card's Cancel action, whose click travels through `TimelinePanel.handleStopRun` `@anchor:test-plan-handle-stop-run` and `agentActivity.stopRun` `@anchor:test-plan-stop-run`. The test substitutes `callBackend`'s HTTP transport response only. Restoring either former bare non-Tauri fallback removes its corresponding `start_run` or `stop_run` request and fails the same UI-driven assertion.

## 9. Completeness measure (TP-Q2)

**No numeric coverage gate.** The completeness measure is the **FR-traceability matrix**: every FR (and every TD invariant) maps to named tests. Maintained as `docs/test-matrix.md`, seeded now with the §3 named-invariant sweep. **Checked by a script, not reviewer memory:** CI validates that every FR and property defined in the constitution has a matrix row, that every row names tests with active definitions, and that no row is orphaned by a blank line. The Windows workflow also checks execution for the test kinds it enforces. The two checks are set out below.

**Before merging**, the maintainer confirms green Windows CI and any other checks that ran for the current PR head. A new commit requires a fresh check of the Windows result and every other check that ran. This private repository has no branch protection that mechanically blocks a merge when the Windows result is missing or red, or another check is red.

**Existence and execution are separately enforced, and every run says which it proved (#1384, #1814).** `scripts/check-test-matrix.mjs` has two halves:

- **Existence** — always. Every named test resolves to a real, active definition in the suite's own sources, not one disabled by `.skip`/`.fixme`/`.todo`/`#[ignore]`.
- **Execution** — only with `--artifacts <dir>`. Every named test must also appear as *executed* in the results document its own suite produced: vitest's JSON reporter, Playwright's JSON reporter, `cargo test`'s libtest transcript, and `scripts/node-test-results-reporter.mjs` for the node:test suites. A test that is defined but that nothing ran is reported against its row — as a failure for an *enforced* kind, as a named warning otherwise (next paragraph). "Executed" means the body ran — a failing test counts (its own suite reports that), a skipped one does not.

**A skipped execution check always announces itself** (CJ, 2026-09-02). With no `--artifacts`, `npm run matrix:check` proves definitions only and prints a visible banner. An unenforced kind with no artifact in an otherwise execution-checked run names its definition-only status; a required kind with no artifact fails. The self-hosted Windows workflow supplies artifacts to the execution check after its selected suites finish. The hosted `ci.yml` matrix step runs the definition check because its jobs do not collect all four kinds into one artifact directory.

**The gate names its reach on every run.** `--require-kinds` names the kinds whose artifacts must exist and whose tests must have executed. A kind with an artifact outside that list is observed: an unexecuted test produces a warning. The Windows workflow requires `vitest` when it selected the frontend suite and `e2e` when it selected acceptance; it observes the available `rust` and `node` artifacts. Platform-specific tests and standalone benchmarks cannot all execute in that Windows job. The daily scheduled workflow selects all four suite classes. The summary reports which kinds were enforced and observed, so a local definition check cannot be mistaken for CI execution evidence.

**Three row states, not two (CJ, 2026-09-02).** A test that is active in source but runs only *outside* the blocking gate — `@quarantine`-tagged and excluded by `npm run test:e2e:ci` (#1403), or a `tests/perf` benchmark that §6 defines as tracked-but-never-a-PR-gate — is neither `present` nor missing. **The live instances are the §6 benchmarks plus one cross-platform row**: `FR-X-4` and `NI-frontmatter-fold-perf` (`tests/perf` vitest); `P5-comment-fold-bench` and `P6-delivery-apply-bench`, the two `[[bench]]` assertions given rows of their own by CJ's 2026-09-03 ruling on #2234; and `NI-missing-save-as-filesystem-identity`, three `#[cfg(unix)]` rust tests no CI runner executes. The two bench assertions are plain `fn`s their `harness = false` bench binary's own `main` calls — not `#[test]`s — and the `test = false` target is what keeps them out of every `cargo test` run, on any platform. #1814 named #1382's `D23 representative long-form authoring baseline` block as the live quarantine; **that was stale** — #1408 lifted the quarantine, and there is no `@quarantine` tag anywhere in `e2e/` today. The `@quarantine` limb of this rule is therefore live mechanism with no current instance, kept because #1403 keeps the mechanism. It gets its own status, `present-not-gating`, and the checker enforces the distinction across **four cases, not two**: a `present` row naming a test that did not execute fails; a `present-not-gating` row whose every named test *did* execute fails too, so the status cannot outlive the gap it records; a `present-not-gating` row that mixes an executed test with one that did not fails as a relabelled mixed row rather than reading as honest under either status (CJ's 2026-09-03 #2234 ruling, mechanically enforced by #2284 — see below); and a `present-not-gating` row whose named tests *all* stayed unexecuted passes silently, because nothing in a single run can tell "honestly non-gating" from "the gating test broke too" when the status is row-level. `present-not-gating` exempts a row from executing, never from existing — a typo in such a row still fails. #1124 is the incident this vocabulary exists for: 16 `e2e/acceptance.spec.mjs` rows read `present` from the day the rig landed (2026-07-15) until a CI job first invoked the suite a month later. **A §6 benchmark assertion may be named only from a `present-not-gating` row (test-matrix.md's Test IDs legend); this is now checked, not merely stated** — a `present` row naming a test defined inside a `[[bench]]` target its Cargo.toml declares `test = false` fails too, read structurally from the Cargo.toml rather than from directory convention (#2284; `scripts/check-test-matrix.test.mjs`).

**What the gate still does not prove.** The execution check shows that a named test ran, not that it passed or adequately proves the requirement; the suite result and review own those questions. It proves only the venue and artifacts supplied to that run. A `present-not-gating` row records a test that does not run in the blocking gate; the status is row-level, so permanent benchmark tests have separate rows rather than sharing one with gating tests. A missing artifact for an unenforced kind limits that kind to definition checking, and the checker reports the limit. File binding has the specific residuals in (f-1) through (f-3) below.

## 9b. Process rules

- **Spike exemption (CJ-approved, Rule #1, 2026-07-05):** SPIKE code is throwaway, exempt from TDD, and **never merges** — TDD begins at `textops/` (build step 2).
- **Bug-regression policy:** every bug fix starts with the failing test; the test joins the corpus/matrix permanently. (The plan seeds from old-app bug history; this keeps the habit for new bugs.)
- **Unhandled rejections and uncaught errors fail the run (ratified by CJ, 2026-08-28; #1701).** Vitest's run-level "Unhandled Errors" are a required signal, not noise: a suite that ends with one is a **red run even when every test passes**, `dangerouslyIgnoreUnhandledErrors` is never set in any vitest config (`vitest.config.ts`, `vitest.perf.config.ts`), and a run that exits non-zero with every test green is investigated as a defect rather than retried. #1690 is the incident — a fixture defect in `src/editor/EditorShell.test.tsx` failed the required **Suites (Windows, self-hosted)** gate at `1315/1315 passed` (PR #1695), and the escaping rejection was the only thing that made it findable. **Corollary (FR-X-5):** a production path that deliberately leaves a failure unhandled says so at the site with its reason, and is never "tidied" into a `.catch()`.
