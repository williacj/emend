ABOUTME: Technical design for the Cowrite rewrite — architecture decisions (TD-#), component designs, contracts, and risks.
ABOUTME: Satisfies docs/functional-spec.md (D#/FR-#) and docs/ux-design.md; built decision-by-decision with CJ.

**Status:** Complete (2026-07-05). TD-1–TD-8 locked; fresh-eyes review findings incorporated; remaining unknowns are scoped as SPIKE-1…6 with a build/de-risk order. **TD-18** (#698) ratified by CJ 2026-07-30 (DH-7). **TD-20** (#759 project-open routing, with a narrow TD-12 file-list amendment) ratified by CJ 2026-08-18 (DH-7).
**Inputs:** functional spec (D1–D23, FR-*), UX design (J1–J8, chrome, state inventories).

**Source markers:** The `@anchor:id` citations in these product documents point to source comments. Run `rg -n '@anchor:id' src src-tauri` with the cited id to find one. These citations are not automatically checked; read the surrounding code before relying on them.

**TD-16 amendment — 2026-07-26 (ratified by CJ during PR #693 rework).** Ruling 3's
document-aware signature is `parse_changes(doc: Option<DocRef { root, path }>, content: String)`,
not `Option<String>`. Resolving the ruling's own `docs.json` → `fold_changes` path requires the
project root until TD-17's `OpenProject` exists; the struct makes “both root and path, or neither”
structural while keeping `path` as the synthetic-id document segment. The conservative join refuses
ambiguous candidates, but “mis-join is structurally impossible” and “losing durable identity is the
only cost” were too absolute: CRLF disk anchors currently fail to join against CM6's LF-only reopen
text (#447), which also drops the marker from its `chg-`-keyed delivery card and discards its
authoritative group. That behavior is pinned as an explicit degradation pending coordinate-space
reconciliation. Ruling 5's fail-closed mechanism is likewise explicit: a non-colliding `legacy:` id
may still pass the document/generation gate, so a live-field non-match returns `[]` and the card
remains pending; only an omitted decision report falls back to the requested ids.

## 1. Constraints (inherited, non-negotiable)

- Desktop only: macOS + Windows (D23, FR-X-1). No web service, ever (D9).
- Two agentic providers as peers: Claude Code CLI + GitHub Copilot CLI (D10).
- Every on-disk artifact portable: CriticMarkup in the md, documented sidecar schemas, repo-owned skills (D1, FR-X-8).
- Round-trip fidelity md → rich → md is P0, including YAML frontmatter (FR-ED-1).
- Protected-document discipline with atomic delivery (D3/D21, FR-AGENT-5/6); one agent run at a time per project (FR-AGENT-7).
- Secrets in OS keychain only; all network/agent calls from the backend (FR-X-2).

| TD-11 | 2026-07-10 | **Delivery-time CriticMarkup round-trip validation; unrepresentable changes are refused, never escaped.** When `propose_changes` converts a change set into CriticMarkup (§3.2), the app validates — over the **whole rendered change set and its whole accepted (clean) projection, not per-edit** — that it parses back to *exactly* the intended changes and that the accepted projection is delimiter-clean: no marker delimiters that (a) truncate/malform an intended marker or (b) surface as live markup on accept. Validation is a pure `textops` predicate; policy lives in the delivery layer (P2a-13). A failing change is **never** escaped and **never** delivered; the remedy depends on where the offending delimiter lives. **Payload-caused** collisions (in an insertion, or a substitution's `new` — bytes the agent owns) return to the agent as a structured *unrepresentable-revise* response (a distinct discriminated reason, riding the **TD-7** return channel but **not** implying context-staleness) for it to reword. **Existing-text-caused** collisions (delimiter bytes inside the *deleted / `old`* range — text the agent does not own and cannot reword, and which for a sequence like a bare `--}` has *no* single-marker representation at all) are an honest hard-fail surfaced for that edit: it is not tracked, rather than corrupt the doc. Group atomicity carries over (P4b/TD-7): an unrepresentable edit refuses its whole group. | Raised by the P1-3 (#39) review; CJ agreed 2026-07-10; whole-set-predicate + existing-text-vs-payload remedy folded from the PR #80 review. CriticMarkup has **no standard escape**, so any escape scheme would break portability (FR-X-8: pending markup is read *raw* on GitHub diffs and other tools) and reintroduce a view↔file serializer (**TD-2** / P0 fidelity); and a collision that lands part of a payload as *untracked* text in a protected doc violates **D21 / FR-AGENT-2** — so "allow" and "escape" are both non-starters, leaving refuse. Mechanism is first-closer-wins nesting + no escaping: `{++ {--z--} ++}` is one insertion whose content becomes a live `{--z--}` on accept; a payload containing its own closer (`++}`, or `--}` / `~~}` / `~>` for the other marker kinds) truncates the marker and leaks untracked text; and two individually-clean *adjacent* insertions can jointly form a marker (`{--` then `z--}` → accepted `{--z--}`) — which is why the predicate is whole-set, not per-edit. Collision surface is small — fenced code, inline code, and frontmatter are parser-excluded, so a *reveal-on-accept* payload whose accepted text is properly fenced passes; only bare un-fenced marker-shaped prose fails, **plus** own-closer truncation, which code-wrapping the payload does **not** fix (the enclosing `{++` opener sits outside the code span, so the parser still grabs the first inner closer). **Corollary (editor accept/reject wiring, P2a-5):** the editor must apply *interactive/queued* accept-reject decisions against a *single parse snapshot* or a stable change identity — never re-parse-then-positional-index — else a revealed marker misattributes a later decision (documented in `textops::apply`; the batch `apply` already does this correctly). Read-only display-mode projections (P1-7) and the P1-11 delivery partition-apply are whole-document/batch and safe by construction. P2a-13 lands a named test for the refuse-unrepresentable behavior (under P6 delivery coverage); the delimiter-clean-payload constraint also belongs in the `docs/formats/` CriticMarkup doc when P1-13 publishes it. |

### 3.2 MCP tool surface (TD-1 contract, v1)

**Mutating tools** (`propose_changes`) validate against a **document revision token**; conflict handling at delivery is TD-7's per-edit rebasing (genuinely conflicted edits return to the agent as structured partial-stale — no silent rebasing). **Comment-lane tools** (`add_comments`, `reply_to_comment`) carry no revision token (TD-14): every anchor requires a `text_snapshot` and is resolved via TD-6/D17 — verified exactly, fuzzy-re-anchored, or orphaned with the original quote preserved, never silently mis-placed (P2) — and the per-comment placement outcome (`placed`\|`relocated`\|`orphaned`) is returned to the agent.

| Tool | Shape | Notes |
|---|---|---|
| `get_document_state(doc)` | → `{content, revision, pending_changes[], comments[], protection}` | The agent's read path for protected docs |
| `propose_changes(doc, revision, edits[{range, replacement, note?}], summary, change_set_meta)` | → `change_set_id` | App converts to CriticMarkup + TD-4 attribution **atomically**, validating the whole change set's round-trip (TD-11: unrepresentable changes are refused, not escaped); delivers J1 card |
| `add_comments(doc, comments[{anchor (text_snapshot required), body, severity?, skill?, workflow_run?}])` | → per-comment `{id, placement: placed\|relocated\|orphaned}` | J3 findings + ordinary comments; anchors resolved via D17, never rejected for staleness (TD-14) |
| `reply_to_comment(comment_id, body, kind: reply\|defense)` | | FR-CMT-4; defense flagged distinctly |
| `create_document(path, content)` | → opens tab | J2 birth card; direct write allowed (unopened) but through-tool so the app can open/attach |
| `list_documents()` | → paths + protection states | D21 awareness |
| `permission_request(action, detail, why)` | → `allow\|allow_always\|deny{reason}` | J7; Claude Code permission delegation target |

**Correction and the read path (TD-21 ruling 9, PROPOSED — #1125).** `get_document_state.comments[]` omits withdrawn nodes: a withdrawn reply, and any thread whose root is withdrawn (FR-CMT-9 — a withdrawn comment is not among the comments the agent is offered), including one whose only surviving replies are the author's own, which leaves the working view entirely (ruling 4's cascade-hide). **Knowingly deferred (CJ, 2026-08-18):** an agent asked to summarize a discussion does not see a reviewer's reply surviving under a placeholder; the fix, if it bites, is an additive `include_closed`-style read serving placeholder threads flagged, not a nullable body on this published shape. Revised bodies are served **current**, with no edit history and no `edited` marker — v1 browses no versions (D24), so there is nothing for the agent to reach. `reply_to_comment` naming a withdrawn node returns a structured tool error rather than appending, so an agent holding an id from an earlier read is told rather than silently written into a dead thread (fail closed, FR-X-5). **No correction tool exists in v1** — no `withdraw`, no `revise`: D24 confines correction to the actor's own words, and the app never writes one on an agent's behalf.

**J10 child-first read-path implementation note (2026-10-01; TD-21 remains proposed).** CJ's 2026-09-30 FR-CMT-9/J10 amendment supersedes the cascade-hide premise in the proposed paragraph above. The current `get_document_state.comments[]` projects a withdrawn root only when it has a live reply: the root is a context wrapper with `withdrawn: true`, an empty `body`, and no anchor or severity; only live replies are included. A live root carries `withdrawn: false`. A withdrawn root with no live reply is omitted, and withdrawn reply bodies remain absent. This additive result field preserves a late same-author or other-author reply without offering the withdrawn parent's words as an active comment. The local `reply_to_comment` tool refuses an already withdrawn root or reply under the comment write lane, while a late offline reply can still converge. Batch Address still excludes the withdrawn root. The underlying root-publication signal needed for a published root with no reply is a separate D20 dependency; no result here claims it exists.

### 3.2b Sidecar git lifecycle (TD-3/TD-4 seams — review findings H4, H5, M8, M10)

- **Doc identity:** sidecars key on a **per-doc UUID** minted at first sidecar write; a committed `.cowrite/docs.json` maps path↔UUID (rename/move = one map update event — FR-ED-8; scratch-doc adoption = mint on save-in).
- **Merge safety:** Cowrite installs a `merge=union` gitattribute for `.cowrite/**/*.jsonl` (libgit2 supports union) — append-only + union driver makes even same-file-two-branches merges safe. Non-JSONL sidecars (`changes/*.json`, `docs.json`) are single-writer by design.
- **Reviewer-side sync:** reviewers write to the review branch too, so every sync worker (author and reviewer) runs fetch→merge→push with a bounded retry loop for push races. Note: **reviewers therefore need repo write access** — the GitHub invite grants it; documented as a security note (blast radius = the repo, mitigated by branch protection on main if CJ wants it later).
- **PR-lane import (FR-COLLAB-5):** the **author's sync worker is the single designated importer** of GitHub PR comments; event IDs derive deterministically from the GitHub comment ID (idempotent, no duplicates); diff-line→offset mapping computed against the raw file text at the commented commit (TD-6), then re-anchored forward via D17.
- **Worktree→main:** on review completion, squash-merge lands on remote main; the local main checkout is updated via the D18 completion flow (pull with the union driver active; the author's uncommitted sidecar edits survive by format).
- **Who commits on main:** Cowrite auto-checkpoints (TD-8) — debounced app commits of docs + sidecars; never auto-pushes main.

### 3.3 Editor pipeline (TD-2)

CM6 document = the markdown string. Decoration providers draw from **two distinct parses** (TD-13): the **structural** markdown decorations — headings, emphasis, lists, blockquotes — consume a *frontend* `@lezer/markdown` (GFM) parse (render-only; never crosses MCP, never mutates the source string — TD-2/P1); the **CriticMarkup / comment / severity** decorations consume `textops/` parses, which own the canonical coordinate space (TD-6): CriticMarkup regions → redline (braces hidden; reveal-at-cursor per Typora convention, suppressible); comment anchors → highlights; severity margin marks (`● H` — color + letter). Display modes = view-layer transforms of the same string (No Markup/Original are read-only projections). Source view = decorations off: every Markdown marker remains visible and editable, and H1–H6 markers and text inherit the body font size, weight, and line height rather than retaining rich-view hierarchy (CJ, 2026-09-07, #2397). Frontmatter = folded opaque block (never decorated, never touched by diff/markup — carried from baseline rule). Anchor maintenance: CM6 change-sets update sidecar offsets incrementally (no re-parse storms); drift beyond exact mapping → snapshot+context fuzzy re-anchor (D17), orphan on failure. Autosave writes the string verbatim — fidelity is a non-event (TD-2). **Change identity (TD-16):** the redline layer keys every pending change to an **opaque string** identity, never a positional ordinal: the durable TD-4 `chg-` id for a marker that joins to a sidecar record, a snapshot-scoped `snap:<doc>:<generation>:<ordinal>` for one that does not. Grouping follows the same partition — recorded markers take the record's `group`, unrecorded markers auto-group by adjacency among themselves only — so backend-authoritative grouping and P4b's cover for human-authored markers coexist instead of excluding each other. The committed TD-4 sidecar format is unchanged (no D22 migration); the one machine-local disposition is that pre-TD-16 D15 transcript cards (which persisted numeric ids) rehydrate as display-only, their legacy ids coerced to a non-colliding `legacy:<ordinal>` string so they fail UXR-Q4 closed rather than decide wrong (TD-16 ruling 5). **Undo policy (finding M9):** agent deliveries enter the document with `addToHistory: false` — Ctrl+Z never rips out a delivered set; the designed reversal is Reject. Accept/reject actions *are* undoable, each as a single history entry with sidecar state versioned alongside, so editor text and attribution never desync.

### 3.5 Security model

- Secrets: OS keychain only (FR-X-2); GitHub token used backend-side (octocrab, git2 credentials, feedback); provider auth never touches Cowrite (FR-X-9).
- **MCP server binds to loopback with a per-session bearer token** injected into the spawned CLI's config — only children Cowrite spawned can call the tools; tool calls are validated per D21 protection + path-confined to the project.
- Path confinement generalized (the old app protected only review paths): every repo-relative IPC/tool path canonicalized and confined; null-byte/symlink/`..` rejected.
- Protected-doc watchdog: FS watcher on open/review-set docs. **Attribution precedence (finding M11):** FR-AGENT-5 convert-to-tracked-changes happens only on *positive* attribution (write correlated with the agent's streamed file-write events, TD-5); anything unattributable — git checkout, external editor, autosave race — defaults to the FR-ED-7 banner with Compare. Never silently convert on a guess.
- **Multi-instance safety (finding M7):** per-project lock file; opening an already-open project focuses the existing instance's window. One MCP server, one sync worker, one JSONL appender per project — FR-AGENT-7 enforceable by construction. *(The "one MCP server per project" invariant is realized end-to-end by the TD-17 `OpenProject` aggregate — see §2: the bound server, watchdog, and shared protected set live for one project's open→close lifetime; M7's single-project reality is exactly what lets that ownership be a single `Mutex<Option<OpenProject>>` rather than a multi-project map.)* The lock is a content-free OS file lock; owner metadata and the routing rendezvous ride separate unlocked files, because a held Windows lock denies every other handle — including this process's — access to the locked file (TD-12). **Realized and scoped by TD-20 (2026-08-14):** M7 was asserted here from 2026-07-05 and unenforced until TD-20, because the lock module had no caller; routing between instances is now the `instances/` service, and the registry lives per-user in app-local data (`<app_local_data_dir>/instances/<blake3(canonical root)>/`) rather than at `.cowrite/lock*`. **"One live instance per project" therefore means one per user session on one machine** — the only scope in which the second half of this bullet ("focuses the existing instance's window") is performable at all; a folder shared across machines or accounts is governed by TD-4's conflict-free formats and D18's review lane, not by a lock one side could never raise a window for.
- **CSP: the webview has no external network egress** — production `connect-src 'self'` (IPC only). All GitHub/AI traffic originates backend-side (FR-X-2); octocrab/git2 and child-process stdio are not governed by the webview CSP, so the frontend never needs `github.com` reachability. Dev-only HMR relaxations (Vite `localhost`/`ws`, `'unsafe-inline'`) live in Tauri's `devCsp` and never ship in the production `csp`. (Supersedes the earlier `api.github.com`/`github.com` CSP pinning — see TD-9.)
